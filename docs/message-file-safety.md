# C 消息文件读写的边界与错误处理

本次直接修改 `aflnet.c` 中现有的 `construct_kl_messages` 和 `save_kl_messages_to_file`，不新增协议解释器或变异器。两个签名保持不变，现有调用位置继续使用同一实现。变异操作、网络收发、状态识别、队列选择和反馈调度没有修改。

## 输入构造

`construct_kl_messages` 校验必填参数和区域长度，拒绝负边界、倒置范围及超过原分配器上限的消息；长度计算使用检查后的无符号算术。读取不足不再被零填充掩盖。读取、关闭错误和无效区域会清理临时资源并沿用现有 FATAL/PFATAL 契约，而不是返回一个看似成功的消息链。

此接口仍按区域长度连续读取文件，不新增 seek 或区域重排。区域数量为零时允许返回空链，文件剩余字节也不因此被要求消费。成功返回的链由调用方通过 `delete_kl_messages` 释放；文件在函数内关闭。输入区域借用，不由构造器释放或修改。

## 文件保存

`save_kl_messages_to_file` 先预检选中的消息前缀，再分配和复制结果，最后打开输出文件。检查消息指针、正长度、数据指针及累计长度，使用原 `MAX_ALLOC` 上限和减法形式的预算检查，避免在调用分配器之前发生整数回绕。

只保存 `max_count` 内的前缀，后续消息不参与检查。原始模式仍拼接内容，replay 模式仍使用 LE32 长度加内容。空链或 `max_count=0` 仍生成空文件并返回 0。正常返回值仍是保存的总字节数，输入链及消息由调用方拥有。

非法元数据在输出文件打开前拒绝，避免预检失败时截断已有文件。写入和关闭失败沿用致命错误契约；临时缓冲区由函数释放。底层 I/O 失败仍可能留下部分输出，本次不是原子文件替换实现，也不承诺在磁盘故障时保留旧文件。

接口仍依赖调用方提供有效的链结构和与长度相符的存储；不能从 C 指针推断真实分配大小。分配器自身的资源耗尽仍遵循既有处理方式。

## 测试源码与验证状态

新增 `tests/protocol/test_message_files.c`，使用本地临时文件和虚构字符串。测试源码检查正常读写、raw/replay、限量与空输出、截断输入、非法元数据、累计边界，以及预检失败不截断哨兵文件。致命错误通过测试子进程区分受控退出与信号崩溃，不创建 socket 或启动协议服务。

以下是后续使用的显式入口，本轮全部未执行：

```sh
make message-file-tests
make message-file-tests-sanitized
make check-message-files
make check-message-files-sanitized
```

前两个只构建，后两个执行测试；默认 `all` 不新增测试执行。普通与 sanitizer 测试均链接真实 `aflnet.c`，不复制被测实现。

本轮只有源码和静态审阅、补丁格式检查，没有编译、单元、sanitizer 或回归通过结论。真实分配失败、文件系统故障和整个 fuzzer 执行仍未验证。[此前的集成缺口](current-integration-gaps.md) 继续保留，不能把本次文件读写修复称为状态定向变异的完整修复。
